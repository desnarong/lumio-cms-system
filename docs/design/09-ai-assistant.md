# 09 — AI Assistant

> อยู่ในเฟส 2 แต่ **ออกแบบรองรับตั้งแต่ต้น** (โครงสร้างข้อมูล, API, UI ต้องเผื่อไว้)

## 9.1 ฟีเจอร์

| ฟีเจอร์                 | การทำงาน                                                                          |
| ----------------------- | --------------------------------------------------------------------------------- |
| **สร้างเว็บจาก prompt** | "ทำเว็บร้านนวดสปา เชียงใหม่" → ได้หน้า Home/Services/Pricing/Contact พร้อมเนื้อหา |
| **เขียน/ปรับข้อความ**   | เลือกข้อความ → ✨ "ทำให้สั้นลง / เป็นทางการขึ้น / แปลอังกฤษ"                      |
| **สร้างรูป/Alt text**   | เจน alt text อัตโนมัติให้ทุกรูป                                                   |
| **SEO Assistant**       | แนะนำ title/description/keywords                                                  |
| **ผู้ช่วยในแชท**        | "เปลี่ยนปุ่มทั้งหมดเป็นสีส้ม" → ระบบแก้ tokens ให้ (ผู้ใช้กดยอมรับ/ยกเลิกได้)     |

## 9.2 กติกาเหล็ก: AI เสนอเป็น diff

- AI เสนอ **เป็น diff** ให้ผู้ใช้กด **Accept** ก่อนเสมอ **ไม่แก้เองโดยพลการ**
- ทุกข้อเสนอต้องยกเลิกได้ (Reject) และย้อนกลับได้ (Undo)
- AI ไม่แตะ: โดเมน, การชำระเงิน, สิทธิ์ทีม, การลบเนื้อหา

```
┌─ AI เสนอการแก้ไข ────────────────────────────┐
│ เปลี่ยนข้อความ Hero                            │
│ - ร้านกาแฟของเราเปิดทุกวัน                     │
│ + ร้านกาแฟคั่วสดทุกเช้า ส่งตรงถึงบ้านคุณ        │
│                                               │
│           [ ยกเลิก ]   [ นำไปใช้ ]            │
└───────────────────────────────────────────────┘
```

## 9.3 จุดที่ AI ปรากฏใน UI

| ตำแหน่ง                        | การกระทำ           |
| ------------------------------ | ------------------ |
| Inline toolbar (เลือกข้อความ)  | ปรับข้อความ, แปล   |
| ปุ่ม ✨ บนแถบเครื่องมือ editor | สร้าง/ปรับทั้งหน้า |
| Media library                  | สร้าง alt text     |
| Growth > SEO                   | แนะนำ meta         |
| Command Palette / แชท          | สั่งงานภาพรวม      |

## 9.4 สถาปัตยกรรม

```
Admin ──POST /ai/*──▶ API ──▶ AI Provider (ผ่าน abstraction) ──▶ ผลลัพธ์เป็น diff
                                  │
                                  └─ cache (Redis) ตาม hash ของ prompt+context
```

- ห่อผู้ให้บริการ AI ด้วย **abstraction** (สลับโมเดลได้)
- **cache ผลลัพธ์** ตาม hash ของ (prompt + context) เพื่อลดต้นทุน
- งานหนัก (generate-site) ทำเป็น background job แล้วแจ้งเมื่อเสร็จ

## 9.5 API

| Endpoint                 | หน้าที่                                                                                  |
| ------------------------ | ---------------------------------------------------------------------------------------- |
| `POST /ai/generate-site` | สร้างหน้าจาก prompt (คืน block JSON)                                                     |
| `POST /ai/rewrite`       | ปรับข้อความตาม instruction                                                               |
| `POST /ai/alt-text`      | เจน alt text จากรูป                                                                      |
| `POST /ai/translate`     | แปล block/หน้า                                                                           |
| `POST /ai/site-command`  | แปลประโยคสั่งงานทั้งเว็บเป็น design-token patch + inverse patch (ผู้ใช้กดนำไปใช้/เลิกทำ) |

ทุก endpoint: ตรวจ **quota ตามแพ็กเกจ** + rate limit + log การใช้งาน
ผู้ให้บริการ local แปลคำสั่งที่พบบ่อย (สี, มุมโค้ง, ความแน่น, โหมดสี) ได้เองโดยไม่ต้องมี key;
ผู้ให้บริการ OpenAI ต้องตอบ patch ที่ผ่าน `themeTokensPatchSchema` ไม่งั้นระบบถอยไปใช้ parser เดียวกัน

## 9.6 ต้นทุนและโควตา

- กำหนด quota ต่อแพ็กเกจ (เช่น Pro = X ครั้ง/เดือน)
- ใช้โมเดลเล็กกับงานง่าย (alt text, ปรับข้อความสั้น) และโมเดลใหญ่กับ generate-site
- แสดงผู้ใช้เมื่อใกล้หมดโควตา + ทางอัปเกรด

## 9.7 ความเป็นส่วนตัว

- ไม่ส่งข้อมูลอ่อนไหว (ข้อมูลฟอร์มลูกค้า, รหัส) ให้ผู้ให้บริการ AI
- ผู้ใช้เลือกได้ว่าจะให้ AI ใช้เนื้อหาเว็บเป็นบริบทหรือไม่
- ระบุใน Privacy Policy ว่าเนื้อหาอาจถูกส่งไปประมวลผล

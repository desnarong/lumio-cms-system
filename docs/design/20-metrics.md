# 20 — ตัวชี้วัดความสำเร็จ (Success Metrics)

## 20.1 ตัวชี้วัดหลัก

| ตัวชี้วัด | เป้าหมาย | วิธีวัด |
|---|---|---|
| Time to first published site | ≤ 10 นาที | median จาก timestamp สร้างเว็บ → publish แรก |
| Onboarding completion rate | ≥ 70% | % ผู้ใช้ที่จบ wizard 5 ขั้น |
| ผู้ใช้ใหม่ที่ Publish ภายใน 24 ชม. | ≥ 50% | cohort ใหม่ |
| SUS (System Usability Scale) | ≥ 85 | แบบสอบถามผู้ใช้ |
| คะแนน Lighthouse เฉลี่ยของเว็บที่สร้าง | ≥ 90 | Lighthouse CI บนเว็บจริง |
| Support ticket ต่อผู้ใช้ใหม่ | < 0.1 | ticket / ผู้ใช้ใหม่ |
| Retention 30 วัน | ≥ 40% | กลับมาใช้งานใน 30 วัน |

## 20.2 ตัวชี้วัดรอง (leading indicators)

| ตัวชี้วัด | ทำไมสำคัญ |
|---|---|
| เวลาเฉลี่ยต่อการแก้ 1 หน้า | บอกว่า editor เร็วแค่ไหน |
| จำนวน undo ที่ใช้ | ถ้าสูงเกินไป อาจหมายถึง UI ทำให้กดพลาดง่าย |
| อัตราการใช้ Design Panel | บอกว่าคนปรับดีไซน์เองได้หรือยัง |
| อัตราการใช้ Command Palette | บอกว่าคนหาเมนูเจอหรือไม่ |
| จำนวน error toast ต่อ session | บอกว่า UX มีจุดสะดุดไหม |

## 20.3 วิธีวัดความ "ง่าย" (Usability Test)

ให้คนที่ไม่เคยทำเว็บ **5 คน** ทำภารกิจ:

1. เปลี่ยนข้อความหัวเว็บ
2. เปลี่ยนรูป
3. เพิ่มหน้าใหม่
4. เปลี่ยนสีหลัก
5. Publish

**เกณฑ์**: ถ้ามีใครติดโดยไม่มีคนช่วย → กลับไปแก้ UI (ไม่ใช่เขียนคู่มือ)

## 20.4 Dashboard สำหรับทีม (internal)

- Funnel: เปิดใช้ → จบ wizard → publish แรก → กลับมาใน 7 วัน
- Error rate + queue depth (คุณภาพระบบ)
- Cost ต่อเว็บ (storage, CDN, AI)
- Template ที่ถูกใช้มากสุด / น้อยสุด

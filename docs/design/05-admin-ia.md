# 05 — Admin Information Architecture

> อัปเดตตามการ redesign layout ของ admin (ดู [25-admin-redesign.md](25-admin-redesign.md))
> หลักคิด: **菜单แบน 9 ประตู + แท็บในหน้าจอ** — ไม่มีเมนูซ้อนเมนู และไม่มีปุ่มที่กดแล้วไม่เกิดอะไรขึ้น

## 5.1 เมนูหลัก (9 ประตู จัดเป็น 3 กลุ่ม)

Sidebar ซ้ายเป็นรายการแบน (flat) รายการเดียว — สิ่งที่เคยเป็น "เมนูย่อย"
(สไตล์, เมนูนำทาง, SEO, ทีมงาน, แพ็กเกจ ฯลฯ) ย้ายไปเป็น **แท็บภายในหน้าจอ** แทน
เพราะแต่เดิม sidebar กับแท็บในหน้าแสดงตัวเลือกซ้ำกันสองที่

```
Lumio · <ชื่อเว็บ>
─────────────────────────────
งานประจำวัน
  🏠 ภาพรวม            /dashboard
  📄 หน้าเว็บ           /content/page
  ✍️ บทความ            /content/post
  🖼 ไฟล์สื่อ           /content/media
  📥 ฟอร์ม & ข้อความ    /content/forms

ร้านค้า (เมื่อเปิด add-on commerce)
  🛍 ร้านค้า            /commerce/products  → แท็บ: สินค้า · คำสั่งซื้อ · ตั้งค่าร้านค้า

เว็บไซต์
  🎨 ดีไซน์            /design/style       → แท็บ: สไตล์ · เมนูนำทาง · Header/Footer · Template · ส่วน
  📈 เติบโต             /growth/seo         → แท็บ: SEO · สถิติ · ข่าวสาร · สมาชิก · Apps
  ⚙️ ตั้งค่า            /settings/general   → แท็บ: ทั่วไป · โดเมน · ทีมงาน · สำรองข้อมูล · ภาษา ·
                                              อีเมล · การเผยแพร่ · เปลี่ยนเส้นทาง · ส่วนเสริม · แพ็กเกจ
─────────────────────────────
[ ย่อเมนู ]
```

### เหตุผลที่แต่ละกลุ่มอยู่ตรงนี้

| กลุ่ม       | คำถามที่ตอบให้ผู้ใช้                         |
| ----------- | -------------------------------------------- |
| งานประจำวัน | "วันนี้จะแก้/เพิ่มอะไรในเว็บ"                |
| ร้านค้า     | "ขายของ รับเงิน จัดการออเดอร์"               |
| เว็บไซต์    | "ทำให้สวย ทำให้คนเจอ และจัดการเว็บ/ทีม/เงิน" |

### กติกา IA

- **ห้ามเพิ่มประตูที่ 10** — ฟีเจอร์ใหม่ให้ไปเป็นแท็บในหน้าจอที่มีอยู่ หรือเป็น App
- **หนึ่งที่อยู่ = หนึ่งชื่อ** — ทุก URL (รวมแท็บ) มีชื่ออยู่ใน `NAV_SCREENS`
  เพื่อให้ Command Palette กับ breadcrumb เรียกชื่อได้ตรงกัน และไม่มีรายการซ้ำ
- **แท็บที่ role นั้นเข้าไม่ได้ ต้องไม่แสดง** (ไม่ใช่แสดงแล้วกดเด้งกลับ) —
  กรองด้วย `allowedTabs()` ใน `apps/admin/src/shell/nav.ts`
- เมนูที่ผู้ใช้ role นั้นเข้าไม่ได้ → **ซ่อน** ทั้งประตู (ดู [13-rbac.md](13-rbac.md))
- label ใช้ภาษาธุรกิจเสมอ (ดู [04.5](04-ux.md#45-กฎ-ux-ที่ต้องรักษา))

## 5.2 โครงหน้าจอ (Shell)

```
┌──────────────┬──────────────────────────────────────────────────────────────┐
│ Lumio · เว็บ  │  [🔍 ค้นหา ⌘K]      [＋ สร้างใหม่ ▾] [👁 ดูเว็บ] [🌐 EN] (สมชาย) [⎋] │
│ ─────────── │ ──────────────────────────────────────────────────────────── │
│ งานประจำวัน   │  เนื้อหาหน้าจอ (max 1440px)                                   │
│  🏠 ภาพรวม   │   ┌ PageHeader: eyebrow · ชื่อหน้าจอ · คำอธิบาย · [ปุ่มหลัก 1 ปุ่ม] ┐ │
│  📄 หน้าเว็บ  │   └ แท็บของหน้าจอ (ถ้ามี)                                    ┘ │
│  ✍️ บทความ   │   ...การ์ด / ตาราง / ฟอร์ม...                                  │
│  🖼 สื่อ      │                                                              │
│  📥 ฟอร์ม     │                                                              │
│ ร้านค้า       │                                                              │
│  🛍 ร้านค้า   │                                                              │
│ เว็บไซต์      │                                                              │
│  🎨 ดีไซน์   │                                                              │
│  📈 เติบโต    │                                                              │
│  ⚙️ ตั้งค่า   │                                                              │
│ ─────────── │                                                              │
│ [ ย่อเมนู ]   │                                                              │
└──────────────┴──────────────────────────────────────────────────────────────┘
```

| ส่วน    | ขนาด (token)                                                                      | หน้าที่                                                      |
| ------- | --------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| Sidebar | `--layout-sidebar-width` 240px (ย่อเหลือ `--layout-sidebar-collapsed-width` 72px) | ประตู 9 บาน + ชื่อเว็บ + ปุ่มย่อเมนู                         |
| Top bar | `--layout-topbar-height` 64px                                                     | ค้นหา (⌘K) · สร้างใหม่ · ดูเว็บ · ภาษา · ผู้ใช้ · ออกจากระบบ |
| เนื้อหา | `--layout-admin-max-width` 1440px                                                 | PageHeader + เนื้อหาของหน้าจอ                                |

**กติกาของ top bar**: ปุ่มใน top bar ทำงานเหมือนกัน **ทุกหน้าจอ**
(สร้างใหม่ = เปิด dialog สร้างหน้า/บทความ, ดูเว็บ = เปิดเว็บจริงในแท็บใหม่)
จึงไม่ซ้ำกับปุ่มหลักของหน้าจอ ซึ่งเป็น Primary ได้เพียงปุ่มเดียว

## 5.3 PageHeader — หัวหน้าแบบเดียวทั้ง admin

ทุกหน้าจอใช้ component `PageHeader` จาก `@lumio/ui` (ห้ามเขียน `<header>` เอง):

| ช่อง          | ใช้เมื่อ                          | ตัวอย่าง                |
| ------------- | --------------------------------- | ----------------------- |
| `eyebrow`     | บอกว่าหน้าจออยู่ในกลุ่มไหน        | "งานประจำวัน"           |
| `title`       | ชื่อหน้าจอ (`h1` หนึ่งตัวต่อหน้า) | "หน้าเว็บ"              |
| `description` | ประโยคเดียวบอกว่าทำอะไรได้        | "ทุกหน้าของเว็บไซต์นี้" |
| `meta`        | ตัวนับ/สถานะสั้น ๆ                | chip "12 หน้า · 3 ร่าง" |
| `actions`     | ปุ่มของหน้าจอนี้ (Primary ≤ 1)    | [＋ เพิ่มหน้าใหม่]      |
| `tabs`        | แท็บของหน้าจอ                     | สไตล์ · เมนูนำทาง · …   |

## 5.4 Dashboard

1. **หัวหน้า**: "ภาพรวม" + คำอธิบาย + ปุ่ม Primary เดียว = **✏️ แก้เว็บ**
   (เปิด Editor ของหน้าแรก) — "สร้างใหม่" และ "ดูเว็บ" อยู่ที่ top bar แล้ว จึงไม่ซ้ำที่นี่
2. **สถิติวันนี้**: ผู้เข้าชม, ข้อความใหม่, ยอดสมัครรับข่าว (พร้อมแนวโน้ม ↑/↓ %)
3. **คะแนนสุขภาพเว็บ** (วงกลม 0–100) + "สิ่งที่ควรแก้" (กดแล้วไปแก้ได้เลย)
4. **Checklist เริ่มต้น** (ซ่อนได้ และหายไปเมื่อครบ)

### หลักการของ Dashboard

- **ทุกการ์ดต้องกดแล้วทำต่อได้** — ห้ามมีข้อมูลที่ดูได้อย่างเดียวโดยไม่มีทางแก้
- สถิติแสดง **แนวโน้ม** (↑/↓ %) ไม่ใช่แค่ตัวเลขดิบ
- "สิ่งที่ควรแก้" มาจาก SEO score + checklist + alt ที่ขาด (เรียงตามผลกระทบ)
- โหลดเร็ว: ใช้ skeleton ทันที, ดึงข้อมูลแบบขนาน

## 5.5 Admin เป็นเครื่องมือเดสก์ท็อป

| ความกว้างหน้าต่าง | พฤติกรรม                                                                    |
| ----------------- | --------------------------------------------------------------------------- |
| ≥ 1024px          | layout ปกติ (sidebar 240px + เนื้อหา)                                       |
| < 1024px          | sidebar พับเป็นไอคอน + ขึ้นแถบแจ้งว่า "หน้าจัดการออกแบบสำหรับจอคอมพิวเตอร์" |
| เปิดบนมือถือ      | `viewport width=1280` → เห็นทั้งหน้าแบบย่อ (ไม่มี layout มือถือแยกอีกชุด)   |

เหตุผล: การทำ layout มือถือของ admin ซ้ำอีกชุด ทำให้ได้ของที่ด้อยกว่าทั้งสองฝั่ง
ส่วนที่ต้องรองรับมือถือ 100% คือ **เว็บสาธารณะ (renderer)** — ดู
[14-seo-performance.md](14-seo-performance.md) และหัวข้อ "Phone pass" ใน `apps/renderer/src/app/globals.css`

- Editor ยังปรับตามความกว้างหน้าต่าง (inspector กลายเป็นแผงล่างเมื่อแคบ) เพราะเป็นหน้าจอเต็มจอ
- ปุ่ม/ลิงก์ทุกตัวใน admin ยังต้องกดได้ด้วยคีย์บอร์ด และมี focus ring ชัดเจน (WCAG 2.1 AA)

## 5.6 Navigation ภายใน Content

- ทุกหน้ารายการ (list) มี: ค้นหา, กรองตามสถานะ (draft/published), กรองภาษา (เมื่อมี >1 ภาษา)
- ใช้ pagination แบบ cursor (ไม่ใช้เลขหน้า)
- ไม่มี breadcrumb ซ้อนในเนื้อหา — ตำแหน่งปัจจุบันบอกด้วยประตูที่ highlight ใน sidebar
  และชื่อหน้าจอใน PageHeader

# 01 — วิสัยทัศน์และหลักการออกแบบ

## 1.1 วิสัยทัศน์

**Lumio** คือ CMS ที่ทำให้คนที่ไม่เคยทำเว็บเลย สร้างเว็บที่สวย เร็ว และปลอดภัยได้ภายใน
**10 นาที** โดยไม่ต้องอ่านคู่มือ ไม่ต้องเขียนโค้ด และไม่ต้องดูแล server

เราวัดความสำเร็จด้วยคำถามเดียว: *"คนธรรมดาเปิดมาแล้วทำภารกิจพื้นฐานเสร็จโดยไม่ต้องถามใครได้ไหม"*

### เป้าหมายเชิงธุรกิจ (3 ปี)

| เป้าหมาย | ตัวชี้วัด | เป้า |
|---|---|---|
| ผู้ใช้สร้างเว็บสำเร็จ | Time to first published site | ≤ 10 นาที |
| ผู้ใช้กลับมาใช้ซ้ำ | Retention 30 วัน | ≥ 40% |
| ระบบรองรับสเกล | จำนวนเว็บที่แพลตฟอร์มดูแล | 100,000+ |
| ความพึงพอใจ | SUS | ≥ 85 |
| ไม่ต้องพึ่งทีม support | Support ticket ต่อผู้ใช้ใหม่ | < 0.1 |

## 1.2 ปัญหาของ WordPress ที่ต้องแก้

| ปัญหาใน WordPress | วิธีแก้ใน Lumio | หัวข้ออ้างอิง |
|---|---|---|
| เมนู admin เยอะ สับสน (Posts, Pages, Appearance, Plugins, Tools ...) | Admin เหลือ **5 เมนูหลัก** | [05](05-admin-ia.md) |
| แก้หน้าเว็บแล้วต้อง Preview วนไปมา | **แก้บนหน้าเว็บจริง** (Edit on page / WYSIWYG 100%) | [04](04-ux.md) |
| ติดตั้ง plugin เยอะ ชนกัน ช้า ไม่ปลอดภัย | ฟีเจอร์หลักมีในตัว + "Apps" ที่ผ่านการตรวจ sandbox | [16](16-apps.md) |
| ธีมแก้ยาก ต้องรู้ CSS/PHP | ธีมปรับด้วย **Design Panel** (สี ฟอนต์ มุมโค้ง) คลิกเดียว | [08](08-theme-design-panel.md) |
| ต้องอัปเดตเอง ต้องดูแล server | Auto-update, auto-backup, managed hosting | [18](18-deployment.md) |
| SEO ต้องลง plugin | SEO ในตัว + **คะแนนสุขภาพเว็บ** บอกว่าต้องแก้อะไร | [14](14-seo-performance.md) |
| UI ดูเก่า | Design system สมัยใหม่ รองรับ Dark mode | [06](06-design-system.md) |

## 1.3 หลักการ 7 ข้อ

1. **Zero learning curve** — ทุกอย่างทำได้โดยเห็นหน้าจอแล้วเข้าใจเลย
   - ทดสอบด้วย: ให้ผู้ใช้ใหม่ 5 คนทำภารกิจโดยไม่มีคนช่วย ถ้าติดให้กลับไปแก้ UI
2. **Edit where you see** — แก้ตรงที่เห็น ไม่ต้องสลับหน้า
   - คลิกข้อความ = แก้ได้เลย, คลิกรูป = เปลี่ยนรูป
3. **Progressive disclosure** — ซ่อนความซับซ้อน โชว์เฉพาะที่จำเป็น มีโหมด Advanced แยก
   - 3 ระดับ: Simple (ค่าเริ่มต้น) / Pro / Developer — ดู [04](04-ux.md#44-ระดับความซับซ้อน-3-ชั้น)
4. **Beautiful by default** — ทุก template สวยตั้งแต่ยังไม่ปรับแต่ง
   - ค่าเริ่มต้นทุก block ต้องมีเนื้อหาตัวอย่างไทยจริง ไม่ใช่ lorem ipsum
5. **Can't break it** — ย้อนกลับได้ทุกอย่าง (Undo, Version history, Draft/Publish)
   - ทุกการลบมี toast "เลิกทำ" แทน confirm dialog
6. **Fast by default** — เว็บที่สร้างต้องเร็ว (Lighthouse ≥ 90 โดยไม่ต้องทำอะไร)
   - เป้า LCP < 2s, CLS < 0.05 — ดู [14](14-seo-performance.md)
7. **AI as assistant** — ช่วยเขียน ช่วยออกแบบ ช่วยแปลได้ แต่ไม่บังคับใช้
   - AI เสนอเป็น diff ให้กด Accept เสมอ ไม่แก้เองโดยพลการ — ดู [09](09-ai-assistant.md)

## 1.4 หลักการที่ไม่ใช่เป้าหมาย (Non-goals)

- **ไม่ใช่เครื่องมือสำหรับ developer ที่อยากคุมทุกบรรทัด** — คนกลุ่มนั้นใช้ Next.js ตรงๆ อยู่แล้ว
- **ไม่ใช่ self-hosted-first** — โฟกัส managed hosting; self-host ได้แต่เป็น secondary
- **ไม่แข่งเรื่องจำนวน plugin** — เราแข่งเรื่อง "ใช้งานเสร็จเร็วและไม่พัง"

## 1.5 หลักการตัดสินใจ (เมื่อมีทางเลือกหลายทาง)

เวลาต้องเลือกระหว่างสองทาง ให้ใช้ลำดับความสำคัญนี้:

1. **ง่ายกว่าสำหรับผู้ใช้ใหม่** ชนะทุกอย่าง
2. **ย้อนกลับได้** ชนะ "ทำได้เยอะแต่ทำแล้วพัง"
3. **เร็วโดยค่าเริ่มต้น** ชนะ "เร็วเมื่อตั้งค่า"
4. **สวยโดยค่าเริ่มต้น** ชนะ "สวยเมื่อปรับ"
5. **ปลอดภัย** ชนะ "สะดวกแต่เสี่ยง"

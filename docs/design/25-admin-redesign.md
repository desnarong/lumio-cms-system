# 25 — Admin UX/UI Redesign (layout ใหม่ของหลังบ้าน)

> เอกสารนี้บันทึกการ redesign layout ของ `apps/admin` ทั้งชุด
> หลักคิด 3 ข้อ: **ใช้ง่าย · ลดความซับซ้อน · ทุกปุ่มกดแล้วเกิด action**
> พร้อมกติกาแบ่งครึ่งชัดเจน: **admin = เดสก์ท็อป**, **เว็บสาธารณะ = มือถือ 100%**

## 25.1 ปัญหาของ layout เดิม

| ปัญหา                                                                                | ผลกับผู้ใช้                                             |
| ------------------------------------------------------------------------------------ | ------------------------------------------------------- |
| Sidebar เป็น 2 ชั้น (เมนูกลุ่ม + เมนูย่อย) และเมนูย่อยคือแท็บเดียวกับที่อยู่ในหน้าจอ | เห็นตัวเลือกเดียวกันสองที่ ต้องคิดว่า "กดอันไหน"        |
| Sidebar แสดง ~20 ลิงก์พร้อมกัน                                                       | ยาวเกินจอ ต้องเลื่อนเพื่อหาของที่ใช้ทุกวัน              |
| แท็บโชว์ทั้งที่ role นั้นเข้าไม่ได้                                                  | กดแล้วเด้งกลับ Dashboard = ปุ่มที่กดแล้วไม่เกิดอะไรขึ้น |
| Dashboard มีปุ่มลัดซ้ำกับ top bar (สร้างหน้า/เขียนบทความ/ดูเว็บ)                     | ปุ่มเต็มจอ ไม่มี "ปุ่มหลัก" จริง                        |
| แต่ละหน้าเขียน `<header>` + CSS ของตัวเอง (9 ชุด)                                    | หัวหน้าไม่ตรงกัน แก้ทีต้องไล่ 9 ไฟล์                    |
| ทำ layout มือถือของ admin (bottom nav) ซ้ำอีกชุด                                     | ได้ของด้อยกว่าทั้งสองฝั่ง และต้องเทสต์สองเท่า           |

## 25.2 สิ่งที่เปลี่ยน

### 1) Sidebar แบน 9 ประตู ใน 3 กลุ่ม

`เนื้อหา` เคยเป็นเมนูกลุ่มที่มี 6 เมนูย่อย → แตกเป็นประตูอิสระ 5 บาน
(หน้าเว็บ · บทความ · ไฟล์สื่อ · ฟอร์ม & ข้อความ) เพราะเป็นงานคนละชิ้นกัน
ส่วน `ร้านค้า` `ดีไซน์` `เติบโต` `ตั้งค่า` เหลือบานละ 1 บาน
แล้วให้ **แท็บภายในหน้าจอ** เป็นทางเลือกระดับสองเพียงที่เดียว

```
งานประจำวัน : ภาพรวม · หน้าเว็บ · บทความ · ไฟล์สื่อ · ฟอร์ม & ข้อความ
ร้านค้า     : ร้านค้า (แท็บ: สินค้า · คำสั่งซื้อ · ตั้งค่าร้านค้า)
เว็บไซต์    : ดีไซน์ · เติบโต · ตั้งค่า
```

- ข้อมูลอยู่ที่เดียวใน `apps/admin/src/shell/nav.ts`
  - `NAV_DESTINATIONS` = 9 ประตูของ sidebar
  - `NAV_SCREENS` = ทุกที่อยู่ (รวมแท็บ) สำหรับ Command Palette / ชื่อหน้าจอ
  - `visibleSidebar()`, `visibleScreens()`, `activeDestinationId()`, `allowedTabs()`
- ปิด add-on ไหน ประตูนั้นหายทั้งบาน (`feature` ต่อประตู)

### 2) Top bar บางลง และเป็น action กลางของทุกหน้าจอ

`[🔍 ค้นหา ⌘K]  ·  [＋ สร้างใหม่ ▾]  [👁 ดูเว็บ]  [🌐 ภาษา]  (ผู้ใช้ + role)  [ออกจากระบบ]`

- `สร้างใหม่` เป็น SplitButton: กด = สร้างหน้าเว็บ, กากบาท ▾ = สร้างหน้า/บทความ
  (ซ่อนทั้งปุ่มเมื่อ role สร้างไม่ได้)
- ตัดคำทักทาย "สวัสดี คุณ…" ออก (ซ้ำกับชื่อหน้าจอ) แล้วแสดง **ชื่อเว็บ** ที่หัว sidebar แทน
  เพราะข้อมูลที่จำเป็นคือ "กำลังจัดการเว็บไหน"
- ไม่มี bottom bar ของมือถืออีกต่อไป

### 3) `PageHeader` — หัวหน้าแบบเดียวทั้ง admin

component ใหม่ใน `packages/ui/src/page-header.tsx`
(ช่อง: `eyebrow` · `title` · `description` · `meta` · `actions` · `tabs`)

หน้าจอที่เปลี่ยนมาใช้แล้ว: ภาพรวม, หน้าเว็บ/บทความ, ฟอร์ม & ข้อความ, ไฟล์สื่อ,
ร้านค้า, ดีไซน์, SEO, สถิติผู้เข้าชม, ข่าวสาร, Apps, ตั้งค่า
และลบ CSS หัวหน้าที่เขียนเองทิ้ง 9 ชุด (~180 บรรทัด)

### 4) ไม่มีปุ่ม/แท็บที่กดแล้วไม่เกิดอะไรขึ้น

- `allowedTabs(name, tabs, role, features)` กรองแท็บด้วยกติกา RBAC + add-on เดียวกับ
  `isRouteAllowed()` → editor ไม่เห็นแท็บ "ตั้งค่าร้านค้า", admin ไม่เห็น "แพ็กเกจ",
  เว็บที่ปิด add-on ไม่เห็นแท็บของ add-on นั้น
- เรียงแท็บตั้งค่าใหม่ตามความถี่ที่ใช้ (ทั่วไป · โดเมน · ทีมงาน · สำรองข้อมูล · …)
- ตรวจด้วยเทสต์ `apps/admin/src/shell/screen-tabs.test.tsx`

### 5) Admin เป็นเครื่องมือเดสก์ท็อป

| ความกว้าง | พฤติกรรม                                                                     |
| --------- | ---------------------------------------------------------------------------- |
| ≥ 1024px  | sidebar 240px + เนื้อหา (max 1440px)                                         |
| < 1024px  | sidebar พับเป็นไอคอน 72px + แถบแจ้ง "ออกแบบสำหรับจอคอมพิวเตอร์"              |
| มือถือ    | `apps/admin/index.html` ตั้ง `viewport width=1280` → เห็นหน้าเดสก์ท็อปแบบย่อ |

- ลบ CSS มือถือของ shell (bottom nav + media query 767px) ออกทั้งหมด
- token ใหม่: `--layout-admin-min-width`, `--layout-admin-max-width`,
  `--layout-topbar-height`, `--layout-tap-target` (อยู่ใน `packages/tokens`)
- sidebar ที่พับยังคงชื่อเมนูไว้ใน a11y tree (visually-hidden ไม่ใช่ `display:none`)
- เพิ่ม skip link "ข้ามไปที่เนื้อหา"

### 6) เว็บสาธารณะรองรับมือถือ 100%

เพิ่ม "Phone pass" ใน `apps/renderer/src/app/globals.css` และ `shop.css`:

- พื้นที่กด ≥ `--layout-tap-target` (44px) สำหรับลิงก์เมนู header/footer,
  ปุ่มในเนื้อหา, chip หมวดหมู่, ปุ่มในตะกร้า
- เว้น `env(safe-area-inset-*)` ให้ header/footer, แผงเมนู และปุ่มกลับขึ้นบน
- ตาราง/โค้ดที่กว้าง เลื่อนในกรอบตัวเอง (`overflow-x:auto`) ไม่ดันหน้าให้เลื่อนตาม
- ชื่อหน้าใช้ `clamp()` ไม่ล้นจอ
- หน้าสินค้า: ตารางสเปคเหลือคอลัมน์เดียวที่ ≤ 480px, รูปในตะกร้าเล็กลง, ปุ่มกว้างเต็มมือ
- block ทั้งหมดยังคงกติกาเดิม: grid เริ่มที่ 1 คอลัมน์ แล้วขยายที่ 640/1024px
  (มีเทสต์กันถอยหลังใน `packages/blocks/src/responsive.test.ts`)

## 25.4 กติกาที่ต้องรักษาต่อจากนี้

1. เพิ่มหน้าจอใหม่ = เพิ่มใน `NAV_SCREENS` เสมอ (palette จะเจอเอง) และถ้าเป็นงานหลักค่อยเพิ่มประตู
   (ห้ามเกิน 9 ประตู)
2. หน้าจอใหม่ต้องเริ่มด้วย `PageHeader` ห้ามเขียน `<header>` เอง
3. หน้าจอที่มีแท็บ ต้องกรองแท็บด้วย `allowedTabs()`
4. ปุ่มที่ใช้ได้ทุกหน้าจอ (สร้างใหม่/ดูเว็บ/ค้นหา/ภาษา) อยู่ที่ top bar ที่เดียว
5. CSS ของ admin ห้ามเพิ่ม media query แบบมือถือ; CSS ของ renderer ต้องตรวจที่ 360px เสมอ

## 25.6 Editor (edit-on-page) redesign

ปัญหาเดิม: ปุ่มโหมด "แก้ไข / ดีไซน์" บนtoolbar **กดแล้วไม่เกิดอะไรขึ้น** (state ถูกเก็บไว้แต่ไม่มีอะไรอ่าน),
และปุ่ม ทำซ้ำ/ซ่อน/ลบ ซ้ำกันสองที่ (แถบเครื่องมือบนส่วน + หัวแผงขวา)

| เปลี่ยน | ผล |
|---|---|
| โหมดมีผลจริง: **แก้เนื้อหา** ซ่อนมือจับย้าย/ปรับขนาด, **จัดหน้าตา** แสดงมือจับเหล่านั้นและแผง "ย้ายและปรับขนาดข้อความ" | โหมดค่าเริ่มต้นสงบสำหรับเขียน ของจัดหน้ารวมอยู่ที่เดียว |
| เรียง toolbar ตามลำดับงาน: หน้า+สถานะ → เลิกทำ/ทำซ้ำ → โหมด → มุมมองจอ → บันทึก/ประวัติ/ดูตัวอย่าง/เผยแพร่ | หาของเจอบที่เดิมทุกครั้ง |
| แผงขวาเหลือเฉพาะ "ตั้งค่า" (ทำซ้ำ/ซ่อน/ลบ อยู่บนส่วนนั้นที่เดียว) และมีป้าย "ซ่อนบนมุมมองนี้" เมื่อส่วนถูกซ่อน | ไม่สับสนว่าปุ่มไหนคือตัวจริง |
| เมื่อไม่ได้เลือกส่วน แผงขวาแสดงการ์ด **"วิธีแก้หน้านี้"** (คลิกข้อความ · ลาก ⋮⋮ · กด ＋ หรือ / · โหมดจัดหน้าตา) + ผู้ช่วย AI | ผู้ใช้ใหม่เริ่มเป็นทันที |
| Editor เป็น desktop-only เหมือน admin ทั้งชุด (`min-width: 1024px`, ลบ media query มือถือ) | CSS ลดลง ไม่ต้องเทสต์สองเท่า |

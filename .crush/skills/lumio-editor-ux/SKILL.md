# Lumio Editor UX

อ่าน [`docs/design/04-ux.md`](../../docs/design/04-ux.md) และ
[`docs/design/05-admin-ia.md`](../../docs/design/05-admin-ia.md) ประกอบ

## กฎ UX ที่ต้องรักษา

1. ทุกการกระทำสำคัญ **ยกเลิกได้** — ใช้ Toast "ลบแล้ว — [เลิกทำ]" แทน Confirm dialog
2. ข้อความ error เป็นภาษาคน เช่น "รูปใหญ่เกินไป ลองใช้รูปไม่เกิน 10MB" ไม่ใช้รหัส error
3. Empty state ต้องมีภาพประกอบ + ปุ่มชวนทำต่อ
4. ทุกหน้า admin มีไม่เกิน **1 ปุ่ม Primary**
5. ใช้ภาษาธุรกิจ ไม่ใช้ศัพท์เทคนิค
6. รองรับ Keyboard shortcut + Accessibility (WCAG 2.1 AA)
7. Progressive disclosure: ตัวเลือกขั้นสูงซ่อนในโหมด Pro ขึ้นไป
8. **ทุกปุ่ม/แท็บกดแล้วต้องเกิด action** — แท็บที่ role นั้นเข้าไม่ได้ต้องไม่แสดง
   (กรองด้วย `allowedTabs()` ใน `apps/admin/src/shell/nav.ts`)
9. **หัวหน้าทุกหน้าจอใช้ `PageHeader`** (`@lumio/ui`) — eyebrow/title/description/meta/actions/tabs
10. **action กลางอยู่ที่ top bar ที่เดียว** (ค้นหา ⌘K · สร้างใหม่ · ดูเว็บ · ภาษา · ออกจากระบบ)
    ห้ามทำซ้ำในหน้าจอ เช่น Dashboard ไม่ต้องมีปุ่ม "หน้าใหม่"/"ดูเว็บ" อีก
11. **Sidebar แบน 9 ประตู** (งานประจำวัน / ร้านค้า / เว็บไซต์) — ตัวเลือกย่อยเป็นแท็บในหน้าจอ
    ห้ามเพิ่มประตูที่ 10 และห้ามเอาแท็บไปโชว์ซ้ำใน sidebar
12. **admin = เดสก์ท็อป** (ไม่ทำ layout มือถือ) ส่วน **เว็บสาธารณะต้องดี 100% บนมือถือ**
    ดู `docs/design/25-admin-redesign.md`

## ใช้คำไหน (บังคับ)

| อย่าใช้ | ใช้แทน |
|---|---|
| Post type | หน้า / บทความ |
| Slug | ชื่อลิงก์ |
| Taxonomy / term | หมวดหมู่ / แท็ก |
| Widget / Shortcode | ส่วน / Block |
| Permalink | ที่อยู่หน้าเว็บ |
| Publish | เผยแพร่ |

## ข้อความมาตรฐาน (คัดลอกได้)

| สถานการณ์ | ข้อความ |
|---|---|
| ลบสำเร็จ | "ลบแล้ว — เลิกทำ" |
| รูปใหญ่เกิน | "รูปใหญ่เกินไป ลองใช้รูปไม่เกิน 10MB" |
| ชนกัน | "มีคนอื่นแก้หน้านี้อยู่ ต้องการเขียนทับไหม?" |
| บันทึกอัตโนมัติ | ไม่ต้อง toast |

## Editor (edit-on-page) — ต้องมี

- แถบเครื่องมือเรียงตามลำดับงาน:
  `[← ชื่อหน้า · สถานะ] [เลิกทำ/ทำซ้ำ] [แก้เนื้อหา/จัดหน้าตา] [📱💻🖥] [บันทึก · ประวัติ · ดูตัวอย่าง · เผยแพร่]`
- **สองโหมดต้องต่างกันจริง**: "แก้เนื้อหา" ซ่อนมือจับจัดหน้า, "จัดหน้าตา" แสดงมือจับย้าย/ปรับขนาด
  (ห้ามมีโหมดที่กดแล้วไม่เกิดอะไรขึ้น)
- คลิกข้อความ = inline edit, คลิกรูป = เปลี่ยนรูป
- ปุ่ม ＋ ระหว่าง block, handle ⋮⋮ ลากเรียง, พิมพ์ `/` เรียก slash menu
- ทำซ้ำ/ซ่อน/ลบ/บันทึกเป็นเทมเพลต อยู่บนแถบเครื่องมือของส่วนนั้น **ที่เดียว**
  (แผงขวาเหลือแค่ตั้งค่าของส่วน)
- เมื่อไม่ได้เลือกส่วน แผงขวาแสดงการ์ด "วิธีแก้หน้านี้" + ผู้ช่วย AI
- Undo/Redo ไม่จำกัด + Autosave ทุก 2 วินาที
- สถานะ Publish ชัดเจน (● Draft / ✓ Published)
- Editor เป็น desktop-only เหมือน admin ทั้งชุด

## Dashboard — หลักการ

- ทุกการ์ดกดแล้วทำต่อได้ (ห้ามข้อมูลที่ดูได้อย่างเดียว)
- หัวหน้ามีปุ่ม Primary เดียว = **แก้เว็บ** (เปิด Editor ของหน้าแรก)
- สถิติแสดงแนวโน้ม (↑/↓ %)
- "สิ่งที่ควรแก้" เรียงตามผลกระทบ
- โหลดด้วย skeleton ทันที + ดึงข้อมูลขนาน

## ตรวจสอบก่อนจบ

- ทดสอบ flow ด้วยคีย์บอร์ด
- ตรวจว่าไม่มีศัพท์เทคนิคหลุดในข้อความ UI
- ตรวจว่ามีปุ่ม Primary ไม่เกิน 1 ปุ่ม/หน้า และไม่มีปุ่มที่กดแล้วไม่เกิดอะไรขึ้น
- ตรวจว่าหน้าจอใหม่ใช้ `PageHeader` และแท็บถูกกรองด้วย `allowedTabs()`
- `pnpm --filter @lumio/ui test` + a11y check
